How the Book's Data Fits Together

Every JSON, script, and generated page in this repo, and which one feeds which. Click any box for what the file holds, who writes it, who reads it, and a real excerpt. Snapshot taken 2026-09-21 (events 51–85, 30 nodes).

One session, end to end

  1. A Claude skill (swe-teacher / swe-quizmaster) teaches or quizzes you, then appends one event to events.json. Example: event #85, a Linked Lists quiz on 2026-09-17 with 2 right and 0 wrong.
  2. If the session added a topic, the skill also adds it to nodes.json (structure only) and hand-writes the page prose and its coverage log.
  3. The skill runs scan-book.mjs. It replays every Linked Lists quiz (09-11 had 2 wrong, so the streak reset to 1; 09-17 was clean, so the streak is 2). A streak of 2 means a 7-day gap, so the topic is due 09-24 and its status is solid. The script writes book-graph-data.json and progress-data.json.
  4. The skill runs build-progress.mjs, which pastes HTML built from progress-data.json between marker comments in index.html and review-schedule.html.
  5. activity.html needs no build step: it loads events.json in your browser each time you open it.

Lean check

Without the typed-in status, the whole system is one pipeline: two inputs (events.json and nodes.json) → one script that computes status (scan-book.mjs) → two JSON files → one renderer (build-progress.mjs) → pages. Everything outside that line is a candidate to cut or fold in:
